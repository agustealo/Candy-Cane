# Candy Cane documentation manifest

## Screenshot authority

Public-facing Candy Cane screenshots are generated by the deterministic `tests/docs-showcase.sh` runtime and `tests/browser/docs-showcase.mjs` capture pipeline.

The showcase runtime uses a clean WordPress installation, the current Candy Cane theme, real posts, pages, categories, comments and menus, deterministic editorial artwork, and pinned Chromium/Playwright tooling. External images and synthetic theme mockups are not part of the screenshot authority.

The `Docs Showcase` workflow owns freshness. On same-repository pull requests it synchronizes regenerated documentation assets into `docs/screenshots/` and promotes the generated 1200×900 `theme-screenshot.png` capture to the root WordPress `screenshot.png`. On `master` it regenerates the showcase and byte-compares both authorities with the committed files, failing if the public documentation imagery or the WordPress theme preview is stale.

## Canonical visual assets

The following committed files under `docs/screenshots/` are the documentation authority:

- `desktop-home.png` - primary README and repository hero
- `desktop-single.png` - editorial single-post presentation
- `desktop-page.png` - page and sidebar presentation
- `tablet-home.png` - responsive tablet home grid
- `mobile-home.png` - compact home experience
- `mobile-single.png` - compact editorial experience
- `desktop-keyboard-overlay.png` - keyboard-visible image-card overlay
- `showcase-manifest.json` - generated route, viewport and capture metadata

The root `screenshot.png` is the canonical WordPress theme preview. It is generated from the same clean showcase runtime at 1200×900 rather than maintained as a separate mock image.

Regression screenshots from `tests/browser-artifacts/` remain engineering evidence and must not be used as public marketing imagery.

## Documentation surfaces

`README.md` uses `desktop-home.png` as the primary visual and selected feature captures for product context. `docs/SCREENSHOTS.md` is the complete visual gallery and explains what each documentation asset demonstrates. WordPress uses the root `screenshot.png` on theme-selection surfaces.

The whole `docs/` tree is marked `export-ignore`, so visual documentation never enters the customer-installable Candy Cane ZIP. The root `screenshot.png` intentionally remains in the package because it is part of the WordPress theme contract. The runtime Docker context excludes repository-only documentation media as well.
